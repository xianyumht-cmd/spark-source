## 3. 入口还原

PE 入口处机器码：

```asm
03883820  E9 9B A1 0D 02    jmp 0595D9C0
03883825  CC                int3
...
```

跳转目标 `0x0595D9C0` 的首个包装节点可等价表达为：

```c
typedef struct VmEntryFrame {
    uint32_t next_node;
    uint32_t state;
    uint32_t token;
} VmEntryFrame;

_Noreturn void protected_entry(void) {
    VmEntryFrame frame = {
        .next_node = 0x058EA33E,
        .state = 0,
        .token = 0x94ABC499,
    };
    vm_dispatch_058B0B0D(&frame);
}
```

以上常量来自实际机器码，不是推测。真实实现通过覆盖三次 `push` 后的栈槽完成帧构造，然后以 `jmp` 而不是 `call` 进入 `0x058B0B0D`。

## 4. 统一调度器与虚拟化节点

对所有可落盘节区扫描 `E9 rel32`，确认至少 **14** 个节点直接跳往统一地址 `0x058B0B0D`。节点普遍具有以下结构：

```text
保存 3 个寄存器
写入 token / state / next_node 三个 32 位值
交换栈顶值
跳往 0x058B0B0D
```

调度区存在大量：

- 以 `ESI` 类似字节码指针、`EBX` 类似虚拟栈指针的读写；
- 动态计算目标后执行间接跳转；
- 无语义标志位扰动、无效指令字节和跳过式垃圾块；
- 运行时解码常量与间接分派。

这解释了普通线性反汇编出现大量错误边界和不可读伪代码的原因。当前无法从静态镜像可靠确定保护产品名称，因此文档只将其称为“虚拟化/加密保护层”。
