## 关键阻塞

原始 `.text/.rdata/.data` 在磁盘中没有原始数据。需要运行时解密/解压后的内存镜像，静态文件本身不足以恢复完整函数体。

## 下一阶段：动态解包

推荐仅在隔离 Windows 虚拟机中执行：

1. 使用 32 位调试器加载哈希匹配的文件；
2. 在 `ntdll!NtAllocateVirtualMemory`、`ntdll!NtProtectVirtualMemory`、`kernel32!VirtualAlloc`、`kernel32!VirtualProtect`、`kernel32!LoadLibraryA/W`、`kernel32!GetProcAddress` 设置断点；
3. 记录写入原 `.text` RVA `0x1000`、`.rdata` RVA `0x1B8000`、`.data` RVA `0x6D8000` 的时点；
4. 当控制流离开保护节并进入已回填代码区时记录 OEP；
5. 生成完整内存转储并重建 IAT；
6. 用 `tools/analyze_pe.py` 验证转储中的三个常规节已具有非零原始数据；
7. 对解包文件重新执行反编译，并逐函数写入 `src/decompiled/`。

## 验收条件

- 转储可被 PE 解析器正常加载；
- `.text`、`.rdata`、`.data` 不再全部为 RawSize 0；
- 入口不再首先进入当前虚拟机包装节点，或已明确定位真实 OEP；
- 导入表不再只有当前的稀疏表；
- 至少能稳定反编译主初始化路径和窗口初始化路径；
- 每个提交区分“机器码确认”“反编译器推断”“人工命名”，禁止混写。

## 禁止事项

- 不把线性反汇编垃圾区当成函数；
- 不根据静态导入表推断程序用途；
- 不声称已恢复原始变量名或注释；
- 不在未隔离的日常 Windows 主机上直接执行样本。
